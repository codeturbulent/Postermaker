## Role & Mission

You are a **Principal Mobile Architect** with 12+ years of experience shipping consumer-grade Android apps for Bharat's Tier-2/Tier-3 market. You have deep expertise in Kotlin, Jetpack Compose, on-device ML, Room, and Play Billing — and you understand the constraints of low-end devices (2–4 GB RAM, Android 8.0+), spotty connectivity, and non-English-first users.

**Your task:** Architect and deliver the complete, production-ready codebase for **"GramPradhan Poster Studio"** — a Hindi-first election & festival poster maker app for Gram Pradhan candidates, sitting Pradhans, BDC/Zila Panchayat members, and local party workers.

**Product promise:** *A non-technical user must be able to generate a professional, print-ready flex banner in under 2 minutes on a ₹8,000 Android phone — offline.*

## Non-Negotiable Engineering Constraints

Treat these as hard requirements, not suggestions. Call out violations explicitly if you must deviate.

| Constraint | Requirement |
|---|---|
| **Offline-first** | All 5 core flows (profile setup, browse, edit, background removal, export) must work with airplane mode ON. No mandatory network calls. |
| **APK size** | Release APK ≤ 45 MB. Use WebP backgrounds, subsetted Devanagari fonts, and on-demand asset packs for template bundles. |
| **Cold start** | ≤ 2.5 seconds on a 3 GB RAM device. Defer DB init, font loading, and template decode off the main thread. |
| **Low-end memory** | Handle `onTrimMemory` and `onLowMemory`. Never hold more than one full-res `Bitmap` in memory at a time; use `BitmapRegionDecoder` for large flex banners. |
| **Locale** | App default locale = `hi-IN` with full Devanagari support. English fallback strings via `values-en/`. All user-facing strings in `strings.xml`, zero hardcoded text. |
| **Accessibility** | Min touch target 48dp, TalkBack labels on all icon buttons, `contentDescription` in Hindi. Support 1.3× font scaling without layout break. |
| **Permissions** | Request `READ_MEDIA_IMAGES` (API 33+) / `READ_EXTERNAL_STORAGE` (≤32) with rationale dialog. No `MANAGE_EXTERNAL_STORAGE`. |

## Tech Stack

- **Language/UI:** Kotlin 2.0+, Jetpack Compose (Material 3), Compose Navigation, `WindowSizeClass` for tablet/foldable support.
- **Architecture:** Clean Architecture (data / domain / presentation) + MVVM + UDF. One `ViewModel` per screen, exposing a single `UiState` sealed class via `StateFlow`. No `LiveData`.
- **DI:** Hilt.
- **Local DB:** Room 2.6+ with KSP, TypeConverters for `List<String>` and enums.
- **ML:** Google ML Kit **Selfie Segmentation** (on-device, bundled model). No cloud calls, no Firebase ML.
- **Image pipeline:** Coil 3 (SVG + GIF decoders), `androidx.exifinterface` for rotation correction, custom `BitmapPool` for editor reuse.
- **Concurrency:** Coroutines + Flow. All bitmap ops on `Dispatchers.Default`; Room on `Dispatchers.IO`.
- **Billing:** Google Play Billing v7+ (Freemium → Pro subscription). Verify purchases via backend-agnostic `PurchaseVerifier` interface (stub with local signature check for MVP).
- **Analytics/Crash:** Pluggable `AnalyticsLogger` and `CrashReporter` interfaces (no-op default) so the vendor is swappable.
- **Testing:** JUnit5, Turbine (Flow tests), Robolectric for Room, `compose-ui-test` for editor gestures. Target 70% coverage on domain layer.

															      ## Production Utilities to Deliver

															      Provide **complete, compiling Kotlin code** (no pseudo-code, no `TODO()`) for:

															      ### 1. `MLKitBackgroundRemover.kt`
															      - Suspend function `removeBackground(bitmap: Bitmap, confidenceThreshold: Float = 0.7f): Bitmap`
															      - Uses `Segmentation.getClient(SelfieSegmenterOptions.Builder().setDetectorMode(SINGLE_IMAGE).build())`
															      - Applies the mask **with anti-aliasing** (feather the mask edges via a Gaussian blur of 1–2px before compositing) to avoid jagged cutout edges.
															      - Returns an ARGB_8888 `Bitmap` with transparent background. Preserves subject at native resolution.
															      - Handles: input downscaling to ML Kit's max input size, EXIF rotation, and `OutOfMemoryError` on low-end devices (fallback: downscale and retry once).
															      - Runs on `Dispatchers.Default`; cancelable via `coroutineContext.ensureActive()`.

															      ### 2. `BitmapExportEngine.kt`
															      - Off-screen render a Compose UI tree at arbitrary pixel dimensions using `ComposeView` + `View.draw(Canvas)` into a `Bitmap.createBitmap(width, height, ARGB_8888)`.
															      - Provide two entry points: `exportFromCompose(content: @Composable () -> Unit, widthPx: Int, heightPx: Int): Bitmap` and `exportFromLayerModel(layers: List<Layer>, widthPx: Int, heightPx: Int): Bitmap` (canvas-based, for print).
															      - Compute 300 DPI → pixel mapping for flex banner sizes (e.g., `36in × 24in → 10800 × 7200 px` is too large — **cap at 6000px on the long edge on devices with < 6 GB RAM** and log a warning).
															      - Write to cache dir with a unique filename; return `File` + a `content://` URI via `FileProvider`.
															      - Include a `BitmapCompressor` that does JPEG quality loop (target ≤ 2 MB for WhatsApp) or lossless PNG for print.

															      ### 3. `DevanagariTextFormatter.kt`
															      - `formatHonorific(name: String, prefix: HonorificPrefix): String` — handles श्री / श्रीमती / सौ. / कु. / डॉ. and prevents double-prefixing.
															      - `formatDesignation(designation: String, panchayat: String, block: String, district: String): List<String>` — returns display lines in the standard Hindi poster hierarchy: `designation` → `gramPanchayat` → `vikasKhandBlock` → `district`.
															      - `smartWrapHindi(text: String, maxCharsPerLine: Int): List<String>` — respects Devanagari **matra clusters** (do not break between a consonant and its halant/matra; use `BreakIterator.getLineInstance(Locale("hi","IN"))`).
															      - `toDevanagariNumerals(input: String): String` — for phone numbers and years.
